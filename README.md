# 🛒 E-Commerce Performance & Root Cause Intelligence Engine

An automated diagnostic dashboard that tracks e-commerce funnel health and pinpoints **why** conversion and revenue drop, by scanning browser, device and payment-gateway slices and ranking them by how much revenue each one cost.

**🔗 Live demo:** [mallikarjunpb11-maker-ecommerce-root-cause-intellige-app-12ay27.streamlit.app](https://mallikarjunpb11-maker-ecommerce-root-cause-intellige-app-12ay27.streamlit.app/)

> ⚠️ **Data note:** The dataset (`store_data.csv`) is **synthetic**, generated by `make_data.py` with a deliberately injected incident. The findings below demonstrate the method, not real business results. You can upload your own CSV in the sidebar.

## 📌 The Problem

When revenue falls, the first question is *where*. Is it traffic or conversion? And if it's conversion, is it one browser, one device, one payment method, or a combination? Checking this by hand across every slice is slow and error-prone. This tool automates it.

## 🔍 Key Findings (on the included synthetic dataset)

| Metric | Baseline → Incident |
|---|---|
| Revenue | **-33.2%** (incident revenue $214,200) |
| Sessions | -0.2% (traffic was flat) |
| Overall conversion rate | 3.4% → 2.28% |
| Orders | -33.2% (2,856 in the incident period) |

- **It's a conversion problem, not a traffic problem.** Sessions barely moved while revenue dropped by a third.
- **The entire drop sits in one cohort: Safari + iOS + ApplePay.** Conversion in that cohort fell from **3.4% to 0.4%** (-3.0 points), costing an estimated **$105.9K**, which is roughly the whole revenue decline.
- **Every other segment is flat.** The remaining segments moved by 0.01 points or less.
- **The cause can't be narrowed further from this data.** Safari, iOS and ApplePay always occur together here, so the data can't separate browser, device and gateway. The next step would be checking the Apple Pay checkout flow on Safari/iOS.

## 🚀 Features

- **Executive Health Dashboard:** gross revenue, sessions, conversion rate and orders, each compared to the baseline period.
- **Automated Root Cause Slicing:** analyses 1-way, 2-way and 3-way combinations of browser, device and payment gateway.
- **Contribution Loss Scoring:** weights each conversion drop by the segment's share of traffic, so small segments don't trigger false alarms.
- **Material-drop alerting:** the red alert only fires when conversion falls by 0.5 points or more.
- **What-If Recovery Simulator:** set a target conversion rate and average order value to see the projected revenue recovery.
- **Interactive filters and CSV upload:** slice by browser, device and gateway, or load your own data.
- **Exportable diagnostic matrix:** download the full root-cause table as CSV.

## 🧮 Method

1. Split sessions into **Baseline** and **Incident** periods.
2. For every combination of browser, device and gateway (1-way, 2-way and 3-way), compute baseline conversion, incident conversion and the change in points.
3. **Loss Contribution Score** = change in conversion rate × the segment's share of incident sessions.
4. **Estimated lost revenue** = (orders expected at baseline conversion − actual orders) × average order value. AOV is calculated from the baseline data (revenue ÷ orders), not hardcoded.
5. Ignore slices with under 2% of incident sessions to avoid noise.
6. Slices that produce identical results are collapsed into the most specific one, so the headline names the narrowest cohort.

## ⚠️ Limitations

- **Overlapping slices:** a Chrome + Mobile session also counts under Chrome and under Mobile, so loss scores across rows are not additive.
- **Correlation, not causation:** the tool shows *where* conversion broke, not *why*. It points to where an engineer or analyst should look next.
- **Synthetic data:** results are illustrative. Validate on real telemetry before drawing business conclusions.

## ⚡ Run Locally

```bash

git clone https://github.com/mallikarjunpb11-maker/ecommerce-root-cause-intelligence.git
cd ecommerce-root-cause-intelligence

# Install dependencies
pip install -r requirements.txt

# Generate synthetic telemetry
python make_data.py

# Launch dashboard
streamlit run app.py
```
